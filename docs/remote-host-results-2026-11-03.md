# Separate-host v3 onion pilot: client RAM and service request truth

**Validation status, 2026-11-03:** the four selected client whole-RAM images and five additional analyzable images have all been cross-checked against independently written service-run records. The fourth service job concluded **failure** because the Windows clicked client could not acknowledge its `/finish` notification. Its `finally` block still wrote the request-counter JSON and the artifact-upload step succeeded. The server recorded **two** Windows-clicked target requests, matching the client result. The failure is retained as a service-control failure, not silently converted to a successful workflow run.

The [locked protocol and amendments](remote-host-protocol.md) moved the ephemeral v3 onion service to a separate GitHub-hosted Ubuntu runner. Client jobs on separate Linux and Windows runners started independent Tor daemons, loaded the onion landing page in Tor Browser 16.0, and captured whole RAM with AVML or WinPmem while the browser was alive. GitHub job metadata gives distinct service and client runner IDs for every selected pair; the [manifest](../research-results/2026-11-03-remote/manifest.json) records them. A distinct randomized target path existed for each OS × condition. The service counted requests to that path separately from readiness, landing, status, and completion traffic. The one selected image per cell is an engineering pilot, not a detection-rate sample.

For the first three selected clients, the independent [second service record](../research-results/2026-11-03-remote/service-attempt1.json) agrees on target-request counts, service run ID, and hashed onion hostname. The [fourth service record](../research-results/2026-11-03-remote/service-attempt3.json) independently records Linux link 0, Linux click 1, Windows link 0, and Windows click **2** target requests. Its Windows clicked count matches the [client record](../research-results/2026-11-03-remote/windows-clicked-1.json), which also shows two browser click attempts, final browser URL equal to the target, all nine recorded browser PIDs present in RAM `pslist`, an 11.00 GiB whole-RAM image hash, 14 adapter target hits, and 22 generic target-blind YARA target hits. The service records `finish_received: false` for that cell because the final completion notification failed. This notification is for runner shutdown; it is neither a target request nor a RAM analysis result.

The four service dispatches produced **16 actual client job attempts**: nine client jobs completed analysis and seven failed. The four selected client images are the earliest analyzable capture for each cell; five later successful jobs are [released separately](../research-results/2026-11-03-remote/extras/) and not added to the planned one-per-cell denominator. Across all nine analyzable client records, five unclicked links had zero target requests but target-string hits; four clicked jobs had positive target-request counts and target-string hits. The adapter and target-blind YARA each detected the target in all nine. All nine image and target hashes are distinct, and each client's service ID, onion-hostname hash, landing count, and target-request count match its service artifact. These are descriptive extra observations, not independent pre-planned replicate counts. The seven client failures comprise four pre-repair validator argument errors after capture, one Windows landing-page failure, one Linux RAM image whose browser PIDs were absent from `pslist`, and one Windows click that yielded no target request before capture. The [attempt manifest](../research-results/2026-11-03-remote/manifest.json) links every failed, selected, or extra job and the fourth service failure. Earlier service records, including the [pre-repair service](../research-results/2026-11-03-remote/service-prerepair.json) and [third dispatch](../research-results/2026-11-03-remote/service-attempt2.json), retain service-side counters even where clients could not yield an analyzable image.

The [cross-checked aggregate](../research-results/2026-11-03-remote/aggregate.json) can be regenerated from the published JSON files:


Raw RAM and onion private keys were not uploaded. The records release SHA-256 hashes and counts, not URLs or memory strings. This setup confirms distinct hosted runner identities; no Tor circuit packet capture or independently redistributable RAM corpus was produced. The pilot has no `absent` target condition and only one planned capture per cell, so it cannot estimate a target-string false-positive rate or a population detection rate.
